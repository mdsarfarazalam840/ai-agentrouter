# Appwrite Local Deployment Automation Implementation Plan

> **For agentic workers:** Implement this plan task-by-task with test-first changes. Do not commit or push unless explicitly requested.

**Goal:** Make Appwrite production setup and repeat deployments runnable from one local command using an ignored environment file, while preserving Option A's requirement that database and collection IDs are supplied explicitly.

**Architecture:** Extend the existing PowerShell deployment script with strict `.env` loading, preflight validation, per-function environment-variable synchronization, and deployment. Keep Appwrite resource IDs operator-owned: the script never creates or guesses databases, collections, or function IDs. Add a separate setup/check command only for local validation and document the exact first-time steps.

**Tech Stack:** PowerShell, Appwrite CLI 6.1.0 via `npx`, Node.js test runner, existing Appwrite Functions.

## Global Constraints

- The local secrets file is `.env.appwrite.local` and must remain ignored.
- Option A is mandatory: `WEBHOOK_DATABASE_ID` and `WEBHOOK_DELIVERY_COLLECTION_ID` are required inputs; never auto-create or guess them.
- Never print secret values; logs may print variable names and resource IDs only.
- Preserve the existing three function IDs supplied by the operator.
- Profile Insights must not be made public by automation.
- Deployment must run `npm run check`, `npm test`, and `npm run validate:config` before changing Appwrite.

## Planned files

- Create `.env.appwrite.local.example` — safe template with blank secret values and the three supplied function-ID placeholders filled.
- Modify `.gitignore` — ignore `.env.appwrite.local` and deployment state files.
- Modify `scripts/deploy-functions.ps1` — add `-EnvFile`, strict loading, preflight validation, variable synchronization, and deployment.
- Create `scripts/setup-appwrite.ps1` — validate that supplied IDs/resources are reachable without creating resources.
- Modify `package.json` — add local preflight/deploy script documentation aliases only if they do not hide PowerShell errors.
- Modify `README.md` — replace manual per-function variable steps with one-command setup/deploy instructions.
- Create `tests/deployment-config.test.js` — test env parsing/required-variable classification without contacting Appwrite.

## Task 2: Deployment automation

- [ ] Add `-EnvFile` defaulting to `.env.appwrite.local`.
- [ ] Load `KEY=value` lines without overwriting explicitly supplied process environment values.
- [ ] Synchronize function variables using the pinned Appwrite CLI command supported by the installed CLI; if the CLI cannot update variables in-place, stop with the exact command/API gap instead of pretending deployment succeeded.
- [ ] Deploy health-check, github-pr-reviewer, and github-profile-insights using their explicit IDs.
- [ ] Never set Profile Insights execute access to `any`.
- [ ] Run project checks before the first Appwrite mutation.

## Task 3: Documentation and verification

- [ ] Document one-time resource creation and the one-command repeat deployment.
- [ ] Document that API keys must be created once in Appwrite and are never generated by the repository.
- [ ] Run `npm test`, `npm run check`, `npm run validate:config`, `npm audit --omit=dev --audit-level=high`, and PowerShell parse checks.

## Stop conditions

- Stop before deployment if the Appwrite CLI version does not support function environment-variable updates with a verified command/API.
- Stop before deployment if any required secret or Option A resource ID is missing.
- Stop if the operator-managed Profile Insights function cannot be found by its supplied ID.
