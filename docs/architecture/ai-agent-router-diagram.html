Three functions, shared integrations

Runtime overview · doc-wide, static, engineer audience. Authentication is enforced inside handlers; the profile adapter remains an operator integration requirement.

Failure and trust contracts

  • Profile identity is a seam, not a shipped authenticator. Only non-empty identity fields on req.appwrite are checked. No adapter, JWT validation, or execute-permission provisioning is included. Headers and body identity claims are rejected. Configure and verify the trusted adapter before enabling access.
  • At-least-once, not exactly-once. Claim list/create and GitHub list/write races remain. Released attempts can retry; crashed processing attempts block until operator intervention. Lease expiry does not trigger takeover. Issue and PR command replies use direct comment creation and can duplicate after partial failure.
  • Bounds are per operation. The shared LLM budget is 20 seconds, attempts at most 5 seconds, SDK retries disabled. NVIDIA can exhaust the budget before OpenRouter. PR diff is 64 KiB; weekly activity is at most five repositories, ten items per endpoint, concurrency three. Health does not verify providers, credentials, database, or GitHub.

Build and deployment path

PR CI: npm ci → check → validate:config → test → audit. Push/manual deploy: checks, config validation, and tests gate Appwrite CLI 6.1.0 deployments to the production environment. The deploy workflow has no audit step; branch protection and environment approvals are operator settings, not proven here. Only reviewer and health are in Appwrite configuration; profile must already exist.
